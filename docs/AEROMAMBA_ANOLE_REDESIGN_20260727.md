## 0. 为什么推翻上一版

上一版围绕 Falcon-H1-1.5B-Deep 展开，核心主张是"并行混合主干能以 O(1) 每步代价吸收观测
历史"。这个主张是**错的**，而且可以被审稿人用一张表推翻：

Falcon-H1 采用**并行**混合——注意力头与 Mamba-2 头在同一 block 内并行运行。顺序混合之所以
省内存，是因为有些层完全没有注意力、不需要 KV cache；而并行设计**每一层都有完整 GQA
注意力**。按其技术报告 Table 1（66 层、KV heads 2、d_head 128）推算：

```
KV/token = 66 × 2 × 128 × 2 × 2 bytes = 67,584 B ≈ 66 KiB/token
```

对照 Qwen2.5-1.5B（28 层）的 28 KiB/token，**是纯 Transformer 的 2.36 倍**。32k 上下文下
2112 MiB vs 896 MiB。此外 Falcon-H1 官方文档明确写着 1.5B-Deep 这个深配置"训练吞吐下降
25–30%、推理慢相当幅度"，以及"短上下文下 Transformer 略快"——**我们选中的正是作者自己
标注为最慢的变体**。

更根本的是：选了 1.5B 混合模型，逼出了后面一连串坏决定。它塞不下全量微调，所以只能 LoRA；
显存紧张，所以视觉必须冻结；2.48 s/step，所以 K 只能小、步数只能少。**架构选型是所有其它
失败的上游。**

## 1. 参照系：AnoleVLA

AnoleVLA（arXiv 2603.15046，庆应义塾大学，2026-03）用纯深度 SSM 做轻量 VLA：
Meta-World 67.85%、真机 Toyota HSR 63%、216 ms/chunk，比 3B 的 π0.5 快约 3 倍。

架构（论文 Fig. 3 与 §IV）：

- 输入 `x(t) = {s(t), Δs(t), x_v(t), x_l}`
- `s(t)`、`Δs(t)` 各经线性投影成 **1 个 token**
- `x_v(t)` 经 **SigLIP 2 编码，预训练初始化后在演示数据上端到端微调**，再线性投影
- 序列 `H0 = [h_s, h_Δs, h_v, h_l]`，**本体感觉在最前**。原文理由：让循环隐状态在整合视觉
  与语言之前，先被智能体自身状态条件化
- 主干：Mamba-370M，K 个堆叠 Mamba block，**纯 SSM，无注意力**
- 动作头：**从最后一个 token 出发的单个线性投影**。原文理由：循环主干已在末位 token 上完成
  全序列聚合
- 动作：**连续回归、不离散化**，chunk 长度 **H = 50**
- 损失：一阶段 L1 速度损失；二阶段加上加速度损失（动作的时间差分 L1），`L_vel + λ_acc·L_acc`
- 400k 步（200k + 200k），batch 16，AdamW，lr **1e-5**
- **没有对齐阶段、没有 VLM SFT**——预训练 SigLIP2 + Mamba 权重直接在演示数据上端到端训练

## 2. 一个必须先说清的诚实问题

**AnoleVLA 已经发表了"Mamba 做轻量 VLA"这件事。** 我们把它搬到无人机上，就是
"AnoleVLA applied to drones"，架构层面新颖性为零。这一点不能自欺。

新颖性只能来自今天实测出来的、AnoleVLA 不涉及的东西（证据见
`reports/uavflow_stopping_diagnosis_20260727.md`）：

1. **UAV-Flow 缺失的评测协议。** 官方 SR 是人工目视判定、无米制阈值、仓库无代码；`metric.py`
   只算 nDTW。我们的几何 SR 在 OpenVLA-UAV 上得 67.7（宏平均 SR@3m），对照 WorldVLN 复现的
   官方人工 SR 65.61，Rotate 类 20.0 对 20.00 精确吻合。
2. **"策略学不会停"的定量归因。** 我们 0/273 集自主停止，OpenVLA-UAV 202/235（86.0%）。
   评测环没有 stop 接口，终止靠"连续 10 步 < 3 cm"，也就是说停止能力等价于**能否输出零位移**。
3. **根因在标签而非模型。** 训练集只有 11.1% 的轨迹在结尾真正静止，其余在录制结束时仍以
   巡航速度 91.7% 在飞。策略学对了一个说"永不停止"的条件分布。
4. **预测视界与任务尺度不匹配。** K=8 覆盖 0.53 m，任务跨度中位 7.6 m——窗口只占任务 7%，
   "何时到达"在数学上不在预测范围内。K=50 覆盖 6.19 m（81%）。

论文主张应当是**"空中 VLA 为什么停不下来，以及怎么修"**，高效 Mamba 主干是载体不是卖点。

## 3. 目标架构

```
s(t)  ─ Linear ─────────────┐
Δs(t) ─ Linear ─────────────┤
x_v   ─ SigLIP2(可训练) ─ Linear ─┤─→ [s | Δs | vision | text] ─→ Mamba-370M ─→ 末位 token ─→ Linear ─→ [B, K, 4]
x_l   ─ Embed ──────────────┘
```

与现有 `AeroMambaVLA`（`model/uav_mamba_vla.py`）的差距**比预期小得多**：

| 组件 | v1 现状 | 需要改动 |
|---|---|---|
| Token 顺序 | `[state \| delta_state \| vision \| text]`（565–599 行） | **无，已一致** |
| 双本体 token | `proprio_encoder.forward_pair()`（103–109 行） | **无，已一致** |
| 读出位置 | 最后一个有效 text token；该顺序下即序列末位 | **无，等价** |
| 主干 | HF `MambaForCausalLM`，直接调 `.backbone` | 选 `mamba-370m` |
| 加速度损失 | `aero_action_loss` 的 `lambda_acc`（696–699 行） | **无，已存在** |
| 视觉可训练 | 硬编码 `torch.no_grad()` | 已改为按 `requires_grad` 条件化 |
| 动作头 | 3 层 MLP，D→D/2→D/4→K·4 | 已加 `hidden_layers=0` 线性选项 |
| chunk_size | 默认 5 | 配置为 32 或 50 |
| 训练配置 | 无端到端选项 | 已加 `configure_policy_e2e()` |

## 4. 相对 AnoleVLA 的必要偏离

### 4.1 尾部填充（UAV-Flow 专有，AnoleVLA 不需要）

K=50 会让 33% 的轨迹（长度 < 51）不可用。更重要的是，即使可用，标签里也没有"停"。

做法：目标索引超出轨迹末尾时**钳位到最后一帧位姿**。填充段的标签即"保持在终点不动"——这是
真实的（飞手确实停在那儿），也是数据里唯一可能的零位移监督。

代价与收益：

- 全部轨迹在任意 K 下可用，chunk 数不降反升
- 补上了此前完全缺失的停止信号
- 需要限制填充比例，否则大量窗口退化为"原地不动"。用 `terminal_pad_frac` 控制，
  默认允许最多 K/2 步填充

### 4.2 K 的取舍

| K | 保留轨迹 | chunk 数 | 覆盖直线距离（中位） | 时长 |
|---|---|---|---|---|
| 8（旧） | 100% | 233,818 | 0.53 m | 1.6 s |
| 16 | 100% | 201,818 | 1.56 m | 3.2 s |
| 32 | 95.0% | 138,510 | 3.89 m | 6.4 s |
| 50 | 67.0% | 77,864 | 6.19 m | 10.0 s |

（任务起终点直线跨度中位 7.6 m；轨迹长度中位 62 步、均值 66.5。）

先做 **K=32**：覆盖任务约一半，不加填充也保住 95% 轨迹，是较稳的起点；再以 K=50 作对照，
配合尾部填充消除轨迹损失。K 本身要作为消融轴报告——这既是必要的科学性，也直接回应
"预测视界与任务尺度不匹配"这一主张。

### 4.3 序列长度的诚实说明

SigLIP2-base @384 产生 576 个 patch，加指令与 2 个状态 token，总长约 **600–700**。这**低于**
MambaOut 给出的 L > 6D 阈值（D=1024 时约 6,144），也低于 Mamba Policy 报告的 Mamba 超过
FlashAttention 的约 2k 交叉点。

因此**不能主张"Mamba 的线性复杂度在此带来加速"**。真实且可测的主张是：**Mamba-370M 比
Falcon-H1-1.5B-Deep 小 4 倍，因而端到端微调视觉塔与 K=50 长视界在单卡上变得可行**——这是
参数量与显存的论断，不是渐近复杂度的论断。任何延迟对比都必须同时给出参数量。

## 5. 训练方案

遵循 AnoleVLA：**不做对齐阶段、不做 VLM SFT**，预训练 SigLIP2 + Mamba 权重直接在演示数据上
端到端训练。理由是模型从不输出文本，而冻结视觉塔正是我们 `vis_sens ≈ 0.01` 的直接原因。

- 阶段一：L1 速度损失（`lambda_acc=0`）
- 阶段二：`L_vel + λ_acc·L_acc`，复用已有的 `lambda_acc`
- lr 1e-5（AnoleVLA 值；主干是预训练 LM，大 lr 会迅速漂移），AdamW，wd 1e-2
- 轨迹级切分（`--split_by trajectory`），验证集去重

## 6. 验收门

任何改动必须先过这几关才允许全量训练：

| 门 | 判据 |
|---|---|
| G1 过拟合 | 单批次记忆，`pos_err_m` 下降至初值 40% 以下 |
| G2 梯度流 | 视觉塔梯度非零（这是本次改动的核心目的，必须显式验证） |
| G3 不塌缩 | 未见轨迹上 `act_std > 1e-3`，且 `instr_sens` 显著非零 |
| **G4 优于查表** | **未见轨迹上 `pos_err_m` < 0.2271（类均值基线）** |
| G5 停止标签 | 尾部填充窗口的目标末段位移接近零，比例符合预期 |
| G6 闭环停止率 | 显著大于 0（当前 0/273） |
| G7 闭环 SR | SR@3m 向 OSR@3m（63.4%）收敛 |

G4 是这次新增的硬门。此前 `pos_err_m ≈ 0.195` 看似不错，但"只按指令类别查表"就能到 0.2271，
模型只好 14%。没有这条门，任何离线数字都无法解读。

## 7. 对标线

UAV-Flow-Sim 273 集宏平均 SR：WorldVLN 79.12（SOTA）、ImagineUAV 70.9、
**OpenVLA-UAV 65.61（官方最强基线，权重公开可复现）**。

只修停止问题的收益上界是我们当前的 OSR@3m = 63.4，即大致追平 OpenVLA-UAV。要够到
ImagineUAV 与 WorldVLN，停止机制之外还需要别的东西——这一点在立项时就要认清，不能等到
写论文时才发现。

## 8. 已知未决项

- **训练/评测域不匹配**：官方基线服务端 `unnorm_key="sim"`，且 real 与 sim 单位不同（我们已
  独立验证：训练集 `preprocessed_logs` 是米，评测集 `test_jsons` 是厘米）。UAV-Flow-Sim
  正在下载，需在其上训练才可与已发表数字对比。
- **匹配容量对照**：主张架构优势就必须提供参数量对齐的纯 Transformer 对照（MaIL, CoRL 2024
  的方法论标准）。这是必做项，不是可选项。
- **copycat 诊断**：无人机平滑轨迹动作自相关极强，属因果混淆高风险设定。需训练一个只看历史
  动作、不看观测的 probe，报告其能达到的分数。
- **Surround 类判据**：现有几何 SR 对该类是错的（环绕任务成败不在终点位置）。
- **OpenVLA-UAV 缺失的 38 集**需补跑，否则协议验证的 67.7 对 65.61 有运气成分。
