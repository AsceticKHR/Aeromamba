# AeroV3 模型架构验证指引

日期:2026-07-28
配套:`docs/HUGEBENCH_STATEFUL_SMALL_VLA_DESIGN_20260728.md`(架构与依据)、`docs/AEROV3_DATA_BUILD.md`

本文规定 AeroV3 从"能跑"到"结论可信"要依次通过哪些门,以及**每一门失败时该推翻什么**。

原则:**先验证假设,再验证实现,最后才优化效率。** 排序按"若为假则报废的代价"从高到低,不按实现顺序。

---

## 0. 被验证的三条主张

| # | 主张 | 判据 | 状态 |
|---|---|---|---|
| **P1** | HUGE-Bench 在官方观测协议下部分可观测 | 阶段对动作有增量信息 **且** 阶段不可从观测推断 | **已验证,仅 Orbit 族** |
| **P2** | 缺失信息量约 1 bit,紧凑循环状态足以承载 | Orbit 6 阶段,残余不确定性 ≈ 28% | **已估算** |
| **P3** | 策略可因式分解为 $\pi(a \mid z_{\text{ep}}, \text{pose}, \phi)$,视觉可低频化 | 降低视觉更新频率后指标不显著衰减 | **待测(L2.5)** |

P3 是新增的、也是最脆的一条。**它若不成立,整个三时间尺度架构失去依据。**

## 1. 契约测试(CPU,秒级,每次改模型都跑)

`scripts/test_aerov3_wiring.py`,离线(`AEROMAMBA_OFFLINE=1`,小随机模型替身),不需要权重。

必查项:

| 检查 | 期望 |
|---|---|
| 形状 | 动作输出 `(B, 20, 4)`;$z_{\text{ep}}$ `(B, 128)`;$\phi_t$ `(B, 64)` |
| token 顺序 | KV 序列为 `[z_ep | 当前帧 patch tokens]`,顺序稳定且与训练一致 |
| 梯度流 | 冻结视觉编码器与基座 LM 的梯度**恰好为 0**;LoRA / projector / 读出 / 相位单元梯度非零 |
| **状态截断** | $\phi_{t-1}$ 到 $\phi_t$ 的梯度**必须为 0**(§3.3 的 detach 设计),若非零说明 detach 漏了 |
| **缓存等价性** | 缓存 $z_{\text{ep}}$ 与逐步重算 $z_{\text{ep}}$ 的输出**逐位相同**。这是数学恒等式,不是近似;不相等即有 bug |
| 阶段屏蔽 | `subtask_id = -1` 的帧不产生阶段损失梯度 |
| 有限性 | 损失有限,反向后无 NaN/Inf |

`test_v5_head_contract.py` 里那条"文本 key 不能淹没视觉 patch"的回归测试沿用,读出模块换成 AeroV3 的即可。

## 2. 冒烟门(单卡分钟级)

| 门 | 内容 | 失败意味着 |
|---|---|---|
| **G1** 过拟合单批 | 关闭所有正则,单 batch 反复训到损失趋零 | 容量或连线错误 |
| **G1v** 定指令过拟合 | 固定指令,仅靠视觉与位姿驱动动作 | 区分"架构错"与"欠训" |
| **G2** 梯度流 | 冻结部分梯度恒为 0 | 冻结没生效,参数量与效率主张全部作废 |
| **G3** 短程真实数据收敛 | 不塌缩,动作方差不趋零 | 损失权重或归一化有问题 |
| **G4** 阶段头可学 | 阶段准确率显著高于多数类基线 | 相位监督无效,L2 无从谈起 |
| **G5** 逐通道展布 | dz / dyaw 不塌缩 | 通道权重或归一化问题 |

**G4 是 AeroV3 相对旧 v5 门控新增的。** 相位状态是核心贡献,阶段头学不动就没有下文,必须在冒烟阶段就拦住。

## 3. 平凡基线(必须与任何指标同时报告)

单独一个 nDTW 或 TCR 数字不可解释。每次报告都要附:

| 预测器 | 说明 |
|---|---|
| zeros | 全零动作 |
| global-mean | 全局均值动作 |
| **class-mean** | **按指令类别取均值 —— 最强的平凡基线** |
| oracle-traj | 用 GT 轨迹,给出可达上界 |

这条来自 UAV-Flow-Sim 的教训:那里 1.5B 模型的 `pos_err_m` 0.2156,而 class-mean 是 0.2398 —— **只领先 10.1%**,该基准的开环指标已被指令先验饱和。HUGE-Bench 因 episode 长、初始视角随机,论文自身基线的分布也说明未饱和,但**在我们自己的评测子集上必须重新验证这一点**,不能沿用论文的结论。

## 4. 证伪阶梯

按"若为假则报废代价"排序。任一级不过就停下重新评估,不进入下一级。

### L0 — 信息论审计(已完成,零训练成本)

`scripts/hugebench_aliasing_audit.py` 与 `scripts/hugebench_partial_observability.py`。结论:

- 严格混叠占 1.5%,**全部集中在 Orbit 族**(2.3–4.8%),其余任务 0.0%
- Inspect 族:阶段贡献 −5.6%~+1.4%,`acc(S|O)` 0.973–0.983 → **完全可观测**
- Orbit 族:阶段贡献 +22.8%~+55.5%,`acc(S|O)` 0.713–0.883 且**六组中四组低于随机基线** → **强部分可观测**

**聚合数字掩盖了完全相反的两族行为,任何情况下都不可单独引用聚合值。**

### L0.5 — 管线打通(不装 openpi,不跑 π0)

要守住的只有一件事:**训练用数据集存图,评测用现渲图,两者必须一致。** 偏差会造成静默的训练/评测分布错配。

1. **渲染保真检验**(`scripts/hugebench_render_fidelity.py`):渲染若干 GT 状态,与 parquet 同帧存图**逐像素比对**。通过即证明 3DGS 资产、相机约定、坐标对齐三者全对。这是确定性检验,比复现某个标量强得多。
2. **指标合法性检验**:GT 当预测送进 `metric.py` → nDTW 到上限;全零 → 到下限。

> **遗留决策(写作前必须定死)**:若为控制成本只在子集上评测,则论文中 π0 的全测试集数字与我们的子集数字**不可直接比较**。解法是主结果跑完整 test 集、消融才用子集。事后补救不成立。

### L1 — 多模态性判定(一次训练,决定动作头)

训一个流匹配头,比较**随机采样**与**条件均值**两种解码的闭环表现(`2512.01809` 的均值动作测试)。

- 均值不掉点 → 多模态性不成立 → 直接上 NFE = 1–2,省下约 10 倍去噪成本
- 掉点显著 → 拿到 HUGE-Bench 论文里都没有的定量证据,本身可发表

**先验倾向"不掉点"**,因为官方 `--smooth_overlap` 默认把重叠 chunk 在世界系取算术平均,块内多模态在执行前就已被摧毁 —— horizon 20 / exec 10 下每步执行的动作通常是两次独立推理的平均值。若结果如此,这个协议细节就是解释,而非巧合。

### L2 — 相位状态消融(核心贡献)

在 **Orbit 族与 Inspect 族分别**评测三个变体:

| 变体 | 配置 | Orbit 预期 | Inspect 预期 |
|---|---|---|---|
| A | 无状态基线 | 差 | 好 |
| B | 相位状态,**仅动作损失**(复现 RoboMME 失败配置) | 与 A 相当 | 与 A 相当 |
| C | 相位状态,**阶段标签联合监督** | **显著优于 A、B** | **与 A 持平** |

**证伪条件:若 C 在 Inspect 上也显著提升,机制解释就是错的**,须重新分析而不是庆祝。因为 L0 已证明 Inspect 的信息是齐的,那里的提升只能来自别的原因。

B 这一档不可省。它同时验证我们对 RoboMME 失败原因的解释:该文递归变体的四个混淆是 batch 8(其他变体 64)、参数 <10M、浅层旁挂、**仅动作损失驱动**。若 B 也涨了,说明逐步监督不是关键,论证要重写。

**中间量报告**:阶段标注对 test 两个 split 都已释出,因此报告阶段预测准确率,并检验它与任务成功率的相关性。中间量对了终端指标才对 —— 这条链路是可展示的因果证据。

### L2.5 — 视觉频率消融(P3 的证伪点,优先于效率线)

按 §3.1,给定 $(z_{\text{ep}}, \text{pose})$ 后当前帧的增量信息在 Inspect 上有硬上界:pose-only 残差 0.24–0.78 m,信号 11.33 m,故**当前帧视觉的贡献上限是信号量级的 2.1%–6.9%**。该上界对任何以图像为输入的函数成立,不依赖 kNN 这一具体估计器。

做法:在推理步上降低视觉更新频率(每 **1 / 2 / 4 / ∞** 次推理才编码一次当前帧),画指标衰减曲线,Orbit 与 Inspect 分开。

- 曲线平坦 → P3 成立,视觉低频化是免费的效率收益,且是本基准上无人报告过的量
- 曲线陡降 → **P3 被证伪,三时间尺度架构失去依据,推倒重来**

**这一级必须排在 L3 前面** —— 它检验的是假设,L3 检验的只是实现。

### L3 — 效率线

- 前缀缓存(数学上精确,零风险):`observation/first_image` 与 `prompt` 在 episode 内恒定,官方代码每步原样重传
- **四段延迟分解**:视觉 / projector / 主干 prefill / 读出+头,用 CUDA event 计时
- CUDA graph 开关;eager vs FlashAttention(<2048 token 下可能反转)
- 报告口径严格区分**推理频率**与 `exec_steps` 摊薄后的**动作执行频率**
- **渲染时间必须从策略延迟中摘除**,否则测的是模拟器不是模型

参照点:当前 VLM 骨干 UAV 策略最诚实的全机载数字是 VLA-AN 的 **494 ms ≈ 2 Hz**(Jetson Orin NX,2B AWQ)。HUGE-Bench 每步预算 200 ms(267 步 @ 5 fps),即最好的诚实数字仍超预算 2.5 倍。**六个官方基线一个延迟数字都没报**,这条轴是空的。

### L4 — 完整基准 + 等参量对照

若主张任何架构优势,必须补**等参量稠密 Transformer 对照**(MaIL, CoRL 2024 的方法论标准)。这一条没有商量余地 —— RoboMamba 与 AnoleVLA 的加速数字之所以不可引用,正是因为缺了它。

## 5. 算力预算(硬约束)

复现者在 issue #5 报告:**单张 A800,每组实验约 7 天训练 + 7 天评测 = 14 GPU-天**。作者未反驳,只说明其内部使用跨 GPU/跨节点并行。

我们只有一张 4090。上述阶梯若按全量跑,约五组实验 ≈ 70 GPU-天 ≈ 2.3 个月,而窗口在 2026-06-24 就已开始计时。三条应对:

1. **评测成本由渲染主导,而渲染可并行、可缓存。** GT 侧渲染在所有变体间完全相同,必须复用 —— 单这一项就能把多变量消融的评测成本近乎减半。作者另建议:`--num_trajs` 减少轨迹数、按 task/split/env 拆并行作业、多 render server 分端口、调试期降分辨率、先只跑 `test_seen`。
2. **L2 只跑 Orbit 族 + Inspect 阴性对照**,不跑全部 8 类。这个裁剪由 L0 的测量结果背书,不是省事的借口。
3. **小模型是跑得完消融的现实前提**,不只是学术卖点。这一点值得写进论文,它把"为什么做小模型"从风格偏好变成可验证的方法论理由。

## 6. 报告纪律

- 任何 `pos_err` / nDTW / TCR 数字**必须与平凡基线表同时出现**(§3)
- Orbit 族与 Inspect 族**必须分开报告**,聚合值掩盖相反行为
- `test_seen`(指令重叠 95.7%)与 `test_unseen`(5.8%)**必须分开报告**
- 延迟必须给四段分解,且摘除渲染时间
- 任何速度主张必须有等参量对照;**不得声称 SSM 的渐近速度优势** —— 600–700 token 的工作点远低于交叉点
- 跨论文比较 Collision Rate **无效**:HUGE-Bench 的 CR(约 1%)是数字孪生轨迹碰撞判定,AutoFly 的 CR(22–38%)是闭环飞行 episode 失败率
