# 高效有状态小模型:HUGE-Bench 架构选型与实验阶梯

## 0. 主张

> 在 HUGE-Bench 的高层飞行任务上,一个**架构优美的小模型**可以打赢更大的无状态模型,原因不是它更聪明,而是**瓶颈是信息而非容量**——加参数变不出观测里不存在的比特,加状态可以。

这句话的可证伪形式拆成三条,全部已经或可以用低成本实验判定:

| # | 命题 | 判据 | 状态 |
|---|---|---|---|
| P1 | HUGE-Bench 在其官方观测协议下**部分可观测** | 阶段标签对动作有增量信息 **且** 阶段不可从观测推断 | **已验证(仅 Orbit 族)** |
| P2 | 缺失的信息量很小,一个紧凑循环状态足以承载 | 条件熵 ≈ 1 bit | **已估算** |
| P3 | 补上该状态的代价低于它带来的收益 | 端到端延迟增量 < 收益对应的等效算力 | 待测 |

## 1. 我们自己测出的证据(理论核心)

以下两个实验**不训练模型、不下载图像**,只用 4 维 state 列与官方阶段标注,几分钟内完成。其可行性来自一个关键观察:

> HUGE-Bench 场景是**静态**的,因此官方双帧观测 ≡ `(env_id, 初始位姿, 当前位姿)`。图像是位姿的确定性函数,观测的信息内容可以精确地从 state 列计算,无需触碰 180 GB 的图像字节。

**该前提现已由官方 `openpi/scripts/action_infer.py` 的代码确证。** 策略每步收到的字典恰好是四项:

```python
example = {
    "observation/state":       st_w,               # 世界系 [x, y, z, angle]
    "observation/image":       obs_rgb_model,      # 当前帧,256x256
    "observation/first_image": first_obs_rgb_model,# episode 内恒定
    "prompt":                  prompt,
}
```

且作者在 issue #5 中说明:非障碍任务的渲染相机朝向为固定 `omega = -180`、`phi = 0`,只有 `kappa = state[3]`(偏航)随轨迹变化 —— **相机位姿是 state 的确定性函数,不含任何额外自由度**。作者并说明这在 `1_office` 等环境下会呈现接近俯视的视角,且"复现时应保持默认值,不应按任务或环境更改"。

两个推论:

1. **观测比原先设想的更贫瘠**。视角近乎固定俯视意味着图像携带的姿态信息进一步减少,§1.2 的部分可观测结论只会被加强,不会被削弱。
2. **障碍类任务用的是另一套约定**:`state[3]` 被解释为 `phi`,而 `omega` 与 `kappa` 固定。渲染与动作映射都不同,代码里单独分支处理(`convert_state_for_render`)。**任何跨任务统一处理 state[3] 的实现都会在障碍任务上静默出错。** 更隐蔽的是 `--obstacle_angle_mode` 的默认值是 `yaw_legacy` 而不是脚本自己注释为 "new/correct" 的 `phi` —— 默认值是为已发布的旧转换数据准备的,改动前务必确认数据版本。

附带确认:`state[0] + cumsum(actions)` 与 `state[1:]` 的最大偏差为 **0.0000 m**,动作是精确的世界系位姿增量,单位为米,无 UAV-Flow 那种 cm/m 歧义。

### 1.1 观测混叠审计

判据:位置差 < 2 m、偏航差 < 15°、两次访问之间路径弧长 > 20 m,则视为一次混叠重访。K = 20 步(对齐官方 horizon)。

| 指标 | 数值 |
|---|---|
| 分析帧数 | 191,100(600 条训练轨迹) |
| 存在混叠重访的帧 | **1.5%** |
| 真实 K 步位移量级 | 13.90 m |
| **混叠点处的未来分歧** | **22.49 m(量级的 162%)** |
| 随机同轨迹帧对分歧(对照) | 15.03 m |

**严格混叠只占 1.5%,所以任务不是普遍不可解。** 但混叠处的分歧比随机对照还大,说明这些点上两条合法未来指向近乎相反的方向。按任务分解:混叠 **全部集中在 Orbit 族(2.3%–4.8%),其余任务为 0.0%**。绕圈飞行整整一圈后回到同一位姿同一朝向,此时正确动作取决于已绕圈数。Spiral Down 为 0 因为每圈高度不同,Mapping 为 0 因为割草机式覆盖不重访——这两个零反过来证明检测逻辑正确。

### 1.2 部分可观测的两半测试

记忆成为**必需**,当且仅当两个条件同时成立:

- **H1** 阶段标签携带超出观测的动作信息:`E(O,S) << E(O)`
- **H2** 阶段标签无法从观测推断:`acc(S|O)` 低

方法:在同 `(env_id, instruction)` 组内做 8 近邻回归,特征为 `(初始位姿, 当前位姿)`,查询时**排除自身 episode**。14 个密集多阶段组,756 条轨迹。

| 任务族 | E(O) | E(O,S) | 阶段带来的降幅 | acc(S\|O) | 随机基线 |
|---|---|---|---|---|---|
| **Inspect**(4 阶段,8 组) | 0.24–0.78 m | 几乎相同 | **−5.6% ~ +1.4%** | 0.973–0.983 | 0.885–0.953 |
| **Orbit**(6 阶段,6 组) | 3.26–10.01 m | 1.45–7.18 m | **+22.8% ~ +55.5%** | 0.713–0.883 | 0.736–0.847 |

聚合(按帧数加权):真实位移量级 11.33 m,`E(O)` = 2.67 m,`E(O,S)` = 1.88 m(降 29.5%),`acc(S|O)` = 91.2%(随机 87.2%)。

**聚合数字掩盖了完全相反的两族行为,不可单独引用。**

- **Inspect 完全可观测**:阶段贡献为零甚至为负(负值即噪声),阶段可从观测以 98% 精度读出,且 `E(O)` 仅 0.24–0.78 m 对 11.33 m 的信号——无记忆预测器接近完美。**此族加记忆是纯浪费。**
- **Orbit 强部分可观测**:`E(O)` 与信号同阶,无记忆预测器基本失效。最尖锐的一点是 **六组中有四组 `acc(S|O)` 低于随机基线**——位姿近邻不但无助,反而系统性误导,因为同一位姿可分属"接近中/绕行中/返航中"三个阶段。

两个方法论完全不同的实验(混叠、阶段依赖)独立收敛到同一任务族,构成交叉验证。

### 1.3 推论:缺失约一个比特

Orbit 族 6 个阶段,信息上限 log₂6 ≈ 2.58 bit;观测已解释掉大部分,残余不确定性约 28%,**条件熵约 1 bit**。

把 π0 挡在 0.558 的那道墙,在 Orbit 族上本质是**每步约一个比特的状态信息**。这直接决定了架构:

- 参数量是**无效杠杆**——再大的模型也变不出观测中不存在的比特
- 检索式记忆库(MemoryVLA 类)是**错误的抽象**——用高维检索去承载 1 bit 的相位信息,代价与收益严重不匹配
- **一个几十维的显式循环相位状态就够了**,这正是小模型能赢的机制

### 1.4 记忆的作用域

Orbit 族(Orbit-H / Orbit-R / Spiral Down)约占训练集 34%、8 类任务中的 3 类。**记忆应当是任务条件化的,不是全局无差别的。** RoboMME 发现"14 种记忆变体没有普适赢家",很可能正源于此。

### 1.5 必须标注的局限

k 近邻使用**真值位姿**,而真实策略只能从图像推断位姿。因此 `E(O)` 是乐观的信息论下界,不是可达的策略误差。这反而使分解更有用:

- **Inspect 上信息是齐的** → π0 做不好是**感知与学习**问题 → 提升条件表征质量有效
- **Orbit 上信息本身缺失** → 失败是**结构性**的 → 只有状态能解决

两者需要完全不同的改进手段,不可混为一谈。

## 2. 文献纠正:三个不能写进论文的常见说法

### 2.1 "HUGE-Bench 证明流匹配优于回归"——那张表里没有回归头

六个基线中三个共用**完全相同**的 π0 流匹配动作专家,另两个是同一个 OpenVLA 的变体。该对比不存在。

**FastVLM 那一行是天然消融,而且它的结论相反**:动作头完全不变(π0 专家、10 步流匹配、horizon 20、全参微调),只换 VLM 主干,Avg.TCR 从 **0.558 掉到 0.285**。头与头之间的差异不如同一个头换主干的差异大。

> **主导变量是条件表征质量与预训练初始化,不是动作头类型,也不是序列混合器。**

OpenVLA 那一行(nDTW 0.011、CR 0.003)是训练失败的 run——论文表注自己写明"灰色数值因性能过低而比较意义有限,例如原地打转"。不能用它代表"自回归离散 token"这一整类。

### 2.2 "论文证明记忆帮助巨大"——被主干混淆

MemoryVLA(0.234)是 OpenVLA 系,而**无记忆的 π0 是 0.558**,高 2.4 倍。记忆收益只在 OpenVLA 家族内部成立。且论文明说**所有基线都拿到双帧输入**,该基准上不存在真正的无记忆对照组。

正确表述:*在 OpenVLA 主干下,记忆使 NTP 从 0.122 提升到 0.549。*

关于"显式历史帧网格更差"那条负面证据:**附录里一句话、零数字、零消融**,且"due to"后的归因是作者推测而非测量。它与 RoboMME(2603.04639)的大规模受控实验矛盾——后者在同一 π0.5 主干、同一 512 token 记忆预算下比较 14 种变体,**帧采样反而最强(44.51% vs 无记忆 17.93%)**。引用时必须标注为"未量化的报告"。

### 2.3 "Mamba 更快"——在我们的工作点上不成立

`2507.12442` 在 RTX 4090 上的等参数实测:8K token 以下 **Transformer 最多快 1.9×**,反转出现在约 57K。Mamba-3(2603.15569)摘要自陈线性推理"实践中仍是硬件低效的"。MambaOut 的阈值 L > 6D,我们 D=1536 → 阈值 9216,而工作点 600–700。

RoboMamba(3.2B vs LLaMA-7B 基线)与 AnoleVLA(370M 级 vs π0.5 3B 且基线做多步去噪)的加速数字**全部被规模混淆**,不可引用为主干选型依据。

**唯一可用的空白**:全网不存在 Mamba/SSM 骨干的 UAV VLA。但正当主张只有参数效率与显存,**不得声称渐近速度优势**。

## 3. 框架设计:AeroV3

### 3.0 先看任务目标本身要求什么

HUGE-Bench 的评测量是 **TCR@{1,2,5}(轨迹覆盖率)、nDTW(路径相似度)、NTP(分阶段进度)、CR(碰撞率)、CSPL**。除 CR 外全部是**路径级**指标,没有一个是"到达终点即成功"。

> **因此任务本质不是导航到目标,而是执行几何图案。** Orbit 要以正确半径绕、Spiral Down 要以正确螺距下降、Mapping 要以正确条带扫、Inspect 要按序占据多个观察位。终点对了但形状错了同样低分。

而这个基准把两样东西**白送**给策略:

1. `observation/state` 是**精确的世界系位姿**,不需要视觉里程计
2. 场景**静态**,相机朝向除偏航外固定

在这两个条件下,"绕那栋楼飞一圈"一旦知道了**楼在哪**和**自己绕到哪一段**,剩下的近乎是闭式几何。这正好对上 §1 测出来的两件事。

### 3.1 中心主张:策略在这个任务上可以因式分解

> $$\pi(a_{t:t+H} \mid o_{\le t}) \;\approx\; \pi\big(a_{t:t+H} \mid z_{\text{ep}},\; \text{pose}_t,\; \phi_t\big)$$
>
> 其中 $z_{\text{ep}}$ 是 **episode 恒定**的任务框(目标在哪、图案参数),$\phi_t$ 是 **约 1 bit** 的相位。
> **视觉的职责是估计 $z_{\text{ep}}$ 与 $\phi_t$,而不是逐步计算动作。**

这不是设想,是 §1 的两个实验的直接读法。那两个 kNN 实验在**同 `(env_id, instruction)` 组内**检索 —— 组内共享 $z_{\text{ep}}$,等于把任务框免费发给了预测器。在此条件下:

- **Inspect:$E(O)$ 只有 0.24–0.78 m,而信号是 11.33 m。** 给定任务框与位姿,不看任何图像,动作已被决定。
- **Orbit:$E(O)$ 与信号同阶,但补上相位后降 22.8%–55.5%。** 缺的正是 $\phi_t$。

**推论直接决定了架构和效率:既然给定 $(z_{\text{ep}}, \text{pose})$ 后当前帧几乎不携带增量动作信息,视觉就可以跑在远低于控制的频率上。** 这是一条从任务结构导出的效率论证,不是从通用 VLA 技巧套来的。

**在 Inspect 上这个上界已经可以直接算出来。** 任何额外输入至多只能消掉当前残差,而 pose-only 的残差是 0.24–0.78 m、信号是 11.33 m:

> **给定任务身份与精确位姿,当前帧视觉对 Inspect 族动作的贡献上限是信号量级的 2.1%–6.9%。**

这个上界对*任何*以图像为输入的函数都成立,不依赖我们用的是 kNN。它是本设计"视觉低频化"最硬的一块依据。

它同时给出一个尖锐、便宜、且无人报告过的消融:**在大部分推理步丢掉当前帧视觉,性能应当几乎不掉。** 若掉了,说明因式分解不成立,整个设计要重来。

### 3.2 三时间尺度架构

| 尺度 | 模块 | 每 episode 运行 | 输出 |
|---|---|---|---|
| **episode 级** | 任务框编码器(VLM 主干) | **1 次** | $z_{\text{ep}} \in \mathbb{R}^{128}$ |
| **推理级**(exec_steps=10) | 相位滤波器 + 动作解码器 | ~27 次 | $\phi_t \in \mathbb{R}^{64}$、阶段 logits、进度、$A_t \in \mathbb{R}^{20\times4}$ |
| **控制级** | 无(执行 chunk) | 267 次 | — |

**① 任务框编码器。** 输入 `first_image`、`prompt`、初始位姿;冻结视觉编码器(C-RADIO / SigLIP2)+ 小 LM 主干,输出 $z_{\text{ep}}$。由于官方代码里 `observation/first_image` 与 `prompt` 在 episode 内是同一个对象每步原样重传,**这一路的缓存是数学上精确的,不是近似**。

**② 相位滤波器。** 一个极小的循环单元:
$$\phi_t = f_\theta(\phi_{t-1}.\text{detach}(),\; \text{pose}_t,\; z_{\text{ep}},\; [\,\text{当前帧特征}\,])$$
逐步由官方 `subtask_id` 做交叉熵监督,另接一个连续进度回归对齐 NTP。

**③ 动作解码器。** K=20 个动作 query 交叉注意力读出,KV 为 $[z_{\text{ep}}\,|\,\text{当前帧 patch tokens}]$,并与 $(\text{pose}_t, \phi_t)$ 拼接。输出 20×4 世界系位姿增量。

### 3.3 递归怎么训:不做 BPTT,理由是任务结构而非省事

这是本设计最需要辩护的一点。

**做法:状态跨步 detach,每一步都对 $\phi_t$ 施加阶段标签监督。** 训练时采样一段连续的 W(=4)个推理步窗口,窗口内携带状态但切断梯度。

**为什么这样是对的,而不是偷懒:** 我们要的不是通用记忆,是**一个递归的阶段估计器**——本质上是个滤波器。§1.3 已经把缺失信息量钉在约 1 bit。滤波器的更新规则 $\phi_{t-1} \mapsto \phi_t$ 只要一步就能被监督到,不需要通过时间做信用分配。梯度穿越时间是为了让网络学会"何时该记住什么"这种长程信用分配问题;而当每一步的目标状态都由标签直接给定时,这个问题不存在。

**这正好解释了 RoboMME 为什么 14 个递归变体全败。** 该文递归变体的四个混淆是 batch 8(其他变体 64)、参数 <10M、浅层旁挂、以及**仅动作损失驱动**。最后一条是致命的:没有逐步监督,递归状态必须从稀疏的动作误差里自己摸索出该携带什么,那才真的需要 BPTT,而它们没做。对照证据是 RB-VLA(2602.20659):其递归 belief 用**专门的自监督世界模型目标**训练,消融显示去掉 belief 从 77.5% 掉到 32.5%。

> **规律是:递归状态作为主表示 + 专门的表示学习目标 → 有效;作为浅层旁挂 + 仅动作损失 → 无效。** 我们落在前者,且用的是现成标签而非自监督代理目标。

风险与退路:W=4 窗口意味着每个样本 4 次主干前向。若 24 GB 单卡吃不消,退到 scheduled sampling(以概率 p 用 GT 阶段嵌入替代 $\phi_{t-1}$,p 随训练衰减)。

### 3.4 损失

$$\mathcal{L} = \mathcal{L}_{\text{act}} + \lambda_\phi\,\mathcal{L}_{\text{stage}} + \lambda_p\,\mathcal{L}_{\text{prog}}$$

- $\mathcal{L}_{\text{act}}$:20×4 归一化增量上的 L1。**先不上流匹配**,理由见 L1:官方 `--smooth_overlap` 默认把重叠 chunk 在世界系取算术平均,块内多模态在执行前就已被摧毁。
- $\mathcal{L}_{\text{stage}}$:`subtask_id` 交叉熵,逐推理步。
- $\mathcal{L}_{\text{prog}}$:归一化进度 L1,对齐 NTP 的定义。

**不加碰撞头。** π0 的 CR 已经是 1.1%,碰撞不是区分度所在,加了只是装饰。

### 3.5 规模与主干

| | 选择 | 理由 |
|---|---|---|
| 视觉 | C-RADIO-B 或 SigLIP2-base,**冻结** | 已在 `model/vision.py` 跑通;§3.1 说明视觉是低频路径 |
| LM 主干 | **Qwen3-0.6B 稠密**,LoRA | 见下 |
| 可训练量 | LoRA + projector + 读出 + 相位单元 ≈ 30–60M | 单张 4090 可训 |
| 总参数 | **≈ 0.7B**,对 π0 的 3B | sub-1B 空中 VLA 是 §5 指出的真实空白 |

**放弃 Falcon-H1-1.5B。** 三条理由:§2.3 说明我们在 600–700 token 的工作点上无法主张 SSM 的速度优势;混合 SSM-注意力主干至今零 VLA 先例,是不必要的风险;而 §3.1–3.3 已经把状态显式化了,主干**不需要**自带状态。三条合起来指向同一个结论:换成小的稠密主干,论证反而更干净。

**相位机制的成本近乎为零** —— $\phi_t$ 是 64 维,$f_\theta$ 是一个 GRU cell,阶段头是 $64 \to n_{\text{stages}}$ 的线性层。**修复这个失效模式几乎不花计算,因为缺的只有 1 bit。** 这是"效率与能力兼顾"最实在的一处体现:不是靠压缩换速度,是因为诊断准确所以药量极小。

### 3.3 一个已被削弱的前提,以及一个由此暴露的真实瓶颈

先前"一个 267 步 episode 需 267 次完整 prefill"的估算是错的。官方 `action_infer.py` 的默认值是 `--exec_steps 10`,动作 horizon 为 20,故**每次推理执行 10 步**,中位 episode 的策略推理次数约 **27 次**,不是 267 次。跨步状态复用的理论收益因此缩水约一个数量级。

冗余本身是真的:Jetson-PI(2607.12659)实测 π0.5 在 Orin 上重编码(ViT + LLM prefill)占 **55%(朴素)到 70%(系统优化后)**。但每 episode 只有约 27 次推理,所以这条收益应当定位为"锦上添花",不是论文主轴。

**但读代码时发现了一个更重要的事实:渲染是每个执行步都做的,不是每次推理做一次。** `rc.render(...)` 位于内层执行循环内,因此一个 267 步 episode 要向 3DGS render server 发起 **267 次渲染**,GT 侧还要再渲一遍,加上 side-by-side 视频编码。

两个推论:

- **评测的瓶颈是渲染,不是策略。** 这解释了"7 天评测"从何而来,也意味着 §4.0 的加速重点应放在渲染并行与缓存上,而不是让策略更快。**GT 侧渲染在所有消融变体之间完全相同,必须缓存复用** —— 这一项单独就能把多变量消融的评测成本近乎减半。
- **论文里报告"策略延迟"时必须把渲染时间摘出去**,否则测的是模拟器不是模型。这也再次说明为什么六个官方基线一个延迟数字都没报:在这个管线里,端到端 wall-clock 主要由渲染决定。

## 4. 实验阶梯

### 4.0 先算一笔账:算力是硬约束,不是背景条件

issue #5 中一位复现者报告:**单张 A800 上,每组实验约 7 天训练 + 7 天评测,合计 14 GPU-天。** 作者的回应没有反驳,而是确认"我们的内部实验并非围绕单卡全串行工作流设计,渲染与评测使用了跨 GPU / 跨节点的并行作业;单张 A800 跑几天是可能的,不奇怪"。

我们只有**一张 4090**。按原样照搬,§4 的阶梯(L1 一次 + L2 三个变体 + L4 全量与等参对照)约五组实验 = **70 GPU-天 ≈ 2.3 个月**,而窗口在五周前就已开始计时。**这个计划按原样不可执行。**

三条必须写进方案的应对,前两条来自作者本人的加速建议:

1. **评测成本由 3DGS 渲染主导,而渲染可并行、可缓存。** 作者建议:`--num_trajs` 先减少轨迹数、按 task/split/env 拆成并行作业、多个 render server 分端口、缓存已渲染数据、调试期降低分辨率、先只跑 `test_seen`。渲染缓存对我们尤其划算 —— 消融的多个变体在**同一批初始条件**下评测时,GT 侧渲染完全可复用。
2. **L2 消融不需要全部 8 类任务。** §1 已经证明记忆的作用域是 Orbit 族;Inspect 族只作为阴性对照。按任务族取子集评测,规模立刻降一个量级,而且这个裁剪**由我们自己的测量结果背书**,不是省事的借口。
3. **小模型在这里不只是学术卖点,更是让我们跑得完消融的现实前提。** 这一点值得在论文里明说 —— 它把"我们为什么做小模型"从一句风格偏好变成一个可验证的方法论理由。

**在跑任何完整实验之前,先做一次单任务单 split 的最小闭环打通,实测我方硬件上的真实 wall-clock,再据此定阶梯规模。** 这条前置于 L1。

### 4.1 阶梯本体

按**成本递增、每级独立可证伪**排列。任一级不通过则停下重新评估,不进入下一级。

### L0 — 已完成(零成本,不训练)

- ✅ 数据质检:split 设计、指令泄漏(test_seen 95.7% / test_unseen 5.8%)、任务分布、动作单位
- ✅ 观测混叠审计 → 混叠集中于 Orbit
- ✅ 部分可观测两半测试 → P1 成立但仅限 Orbit;P2 估算约 1 bit

### L0.5 — 管线打通(不复现 π0,不装 openpi)

**不跑 π0,也不安装 openpi。** openpi 存在的唯一理由是运行 π0;我们的模型是 PyTorch 的,rollout 循环照 `action_infer.py` 的协议自己写即可(核心循环很短)。砍掉它就砍掉了 JAX、`uv` 和一整套与 PyTorch 冲突的 CUDA 栈。π0 的基线数字直接引用论文。

真正需要守住的只有一件事:**训练用的是数据集里存的图像,评测用的是现渲的图像,两者必须一致。** 相机约定或坐标对齐一旦有偏差,就是静默的训练/评测分布错配 —— 这正是 issue #3 里 nDTW 全 0 的成因。

验证它不需要模型,而且有比"复现某个标量"强得多的办法:

1. **渲染保真检验**:取若干 GT 状态渲染,与 parquet 中同帧存图**逐像素比对**。对得上即证明 3DGS 资产、相机约定、坐标对齐三者全对。这是确定性的像素级检验。
2. **指标合法性检验**:把 GT 当预测送进 `metric.py`,nDTW 应到上限;送全零,应到下限。两点卡住 metric 与 rollout 骨架。

仍需安装的只有 gaussian-splatting(渲染器,**依赖 nvcc 编译 CUDA 光栅化器**)与 `requirements-utils.txt`。

**唯一的遗留问题:若最终为控制成本只在子集上评测,则论文中的 π0 数字(全测试集)与我们的(子集)不可直接比较。** 解法是主结果跑完整 test 集、消融才用子集。这个取舍要在写作前定死,不能事后补。

#### 官方协议常量(取自 `action_infer.py`,复现与对比时必须对齐)

| 参数 | 默认值 | 备注 |
|---|---|---|
| `--exec_steps` | 10 | 每次推理执行 10 步 |
| `--smooth_overlap` | **True** | 重叠 chunk 在世界系取算术平均 |
| `--truncate_to_gt` | True | 预测截断到 GT 长度 |
| `--ndtw_eta` | 3.0 | `nDTW = exp(-DTW / (eta · len(gt)))` |
| `--ndtw_yaw_weight` | 0.1 | 偏航在 DTW 代价中的权重 |
| DTW `softmin gamma` | 0.5 | **是 soft-DTW,不是经典 DTW**,复现时不能用标准库替换 |
| `--obstacle_angle_mode` | `yaw_legacy` | 脚本注释称 `phi` 才是 "new/correct",但默认走旧约定 |
| `--max_steps` | 0 | ≤0 时按每条 GT 轨迹长度自动推断 |

#### 硬件冲突:官方假设两张卡,我们只有一张

官方命令把 render server 放 `CUDA_VISIBLE_DEVICES=0`、rollout 放 `CUDA_VISIBLE_DEVICES=1`。单张 4090(24 GB)上两者必须共存:

- `1_office` 的 3DGS PLY 是 6.89 GB,gaussian-splatting 会把全部高斯载入显存,预计占 5–7 GB
- π0 的 `params` 目录 11.19 GB,JAX 加载后视精度约占 6–11 GB
- **JAX 默认预分配 75% 显存,必须先设 `XLA_PYTHON_CLIENT_PREALLOCATE=false`**,否则渲染服务必然 OOM

合计约 16–18 GB,理论上放得下,但没有余量。若 OOM,退路是把 render server 移到 CPU 或降低渲染分辨率。

### L1 — 多模态性判定(一次训练,决定动作头)

训一个流匹配头,比较**随机采样**与**条件均值**两种解码的闭环表现(`2512.01809` 的均值动作测试)。

- 均值不掉点 → 多模态性在我方数据上不成立 → 直接上 NFE = 1–2,省下 10 倍去噪成本
- 掉点显著 → 拿到 HUGE-Bench 论文里都没有的定量证据,本身可发表

注:HUGE-Bench 的执行协议本身就是强平均操作,主动破坏块内多模态,这使"必须多模态头"的论证进一步削弱。代码层面确认得更狠:`--smooth_overlap` **默认开启**,`ActionPlanAverager` 会把**所有重叠 chunk 对同一时间步的预测在世界系下取算术平均**。也就是说 horizon 20 / exec 10 的设定下,每一步执行的动作通常是两个独立推理结果的平均值。一个真正多模态的策略在这里会被平均成模态之间的插值 —— 而插值往往两边都不是。**若 L1 显示均值不掉点,这个协议细节就是解释,而不是巧合。**

### L2 — 相位状态消融(核心贡献)

在 Orbit 族与 Inspect 族上**分别**评测三个变体:

1. 无状态基线
2. 相位状态,仅动作损失驱动(复现 RoboMME 的失败配置)
3. 相位状态,阶段标签联合监督

预测:变体 3 在 Orbit 上显著优于 1 和 2,在 Inspect 上与 1 持平。**若 Inspect 上也提升,说明我们的机制解释错了,须重新分析。** 这是本方案最重要的证伪点。

附带一个几乎免费、且能支撑因果主张的分析:阶段标注对 test 两个 split 都释出了(`stage_annotations/stage_segments/test_*.jsonl`),因此可以把**阶段预测准确率**作为中间量报告,并检验它与任务成功率的相关性。中间量对了、终端指标才对,这条链路是可展示的。

### L2.5 — 视觉频率消融(因式分解的证伪点)

按 §3.1,给定 $(z_{\text{ep}}, \text{pose})$ 后当前帧的增量信息在 Inspect 上上限只有 2.1%–6.9%。据此在推理步上**降低视觉更新频率**(每 1 / 2 / 4 / ∞ 次推理才编码一次当前帧),观察指标衰减曲线。

- 曲线平坦 → 因式分解成立,视觉低频化是免费的效率收益,且这是本基准上无人报告过的量
- 曲线陡降 → **§3.1 的中心主张被证伪**,架构要推倒重来

这一级比 L3 更该优先,因为它检验的是**假设**而不是**实现**。

### L3 — 效率线

- 前缀缓存(精确优化,零风险)
- 单步延迟四段分解:视觉 / projector / 主干 prefill / 读出+头,CUDA event 计时
- CUDA graph 开关;eager vs FlashAttention(<2048 token 下可能反转)
- 报告口径严格区分推理频率与 `exec_horizon` 摊薄后的动作执行频率

### L4 — 完整基准 + 等参量对照

若主张任何架构优势,必须补等参量稠密 Transformer 对照(MaIL, CoRL 2024 的方法论标准)。

### 重估:FLIGHT VLA 的威胁等级应下调

`2606.06836` 无 arXiv HTML 版的说法有误,全文可读。精读后:

| 维度 | FLIGHT VLA 实际情况 |
|---|---|
| 规模 | **Qwen2.5-VL-3B-Instruct + LoRA**,DiT-B 动作头 |
| 训练资源 | **8× A800 80G / 8× A100 80G** |
| 记忆形式 | **自然语言文本**(Pilot Reasoning 文本写回 memory)+ 末层 hidden state `z_τ` |
| 延迟测量 | **全文零个 ms、零个 Hz、零张效率表** |
| 消融 | **无任何消融表**。仅 Table 2(对基线)与 Table 3(VLM 推理准确率) |
| 评测 | 仅自建 FLIGHT |

**最大的可攻击点:整篇论文的动机是"VLM 推理频率与无人机实时控制固有不兼容",解法是降低 VLM 调用频率——但从头到尾没有报告 VLM 有多慢、动作模型有多快、异步比同步快多少。** 一个以实时性为核心卖点的架构,没有一个时间数字。

其次,"Pilot Reasoning 记忆有效"与"异步有效"这两个中心主张**没有受控消融**。Table 3 只证明了 VLM 经训练后推理准确率从 5.0/6.9 升到 64.2/68.1,那是模块自身指标,不是端到端消融。

第三,其强结果(Long-horizon Flow SR 59.00%)是在自家基准上对**很弱的基线**取得的(OpenVLA-UAV 10.50%、MemoryVLA 18.50%)。在 Fine-grained VLN 上它自己也很弱:SR 13.5% 对 NaVid 13.0%,IASR 11.0% 对 5.0%。

**因此我们的差异化比预想的干净得多:**它 3B、文本记忆、零延迟测量、自家基准;我们小模型、紧凑数值循环状态、实测延迟、第三方基准。**"文本记忆 vs 紧凑状态"还是一个可以直接做的对照实验** —— 按 §1.3,Orbit 缺的是约 1 bit,用自回归生成的整段文本去承载它,代价与收益严重不匹配,这个论点现在有了具体的对照对象。

### 效率轴在 HUGE-Bench 上完全空白

HUGE-Bench 全文中 "real-time" 只出现在描述 3DGS 渲染的语境;**六个官方基线(π0、π0.5、depth-π0.5、FastVLM、MemoryVLA、OpenVLA)一个延迟数字都没报。**

而 episode 中位 267 步 @ 5 fps,即每步 **200 ms** 预算;当前 VLM 骨干 UAV 策略最诚实的机载数字是 VLA-AN 的 **494 ms**,超预算 2.5 倍。**"第一个在 HUGE-Bench 上同时报告任务能力与实测机载延迟的工作"是一个干净、可防守、且无人认领的位置。**

### 其余威胁

递减排列:HUGE-Bench 作者本人(手握全套数据环境基线,repo 至 2026-07-24 仍活跃,基准作者随后发方法论文是常规操作)、浙大 FAST Lab(VLA-AN,唯一可信全机载管线,自述换 Jetson Thor 后冲 10 Hz)、清华 world-model 集群(WorldVLN / WorldFly / ActiveFly-Bench 四个月连发三篇)、Stanford Schwager 组(SINGER + AirVLA,唯一在"机载 + 无人机 + 语言"上有扎实真机记录的美国团队)、南科大 Boyu Zhou 组(OnFly 已做机载部署 + 进度监控 + KV-cache 前缀稳定,几乎是本方案的零样本免训练版)。

### 一个对我们有利的领域观察

2026 年空中 VLA 的主流叙事是 **world model / 未来帧预测**:AeroAct(1.3B)、WorldFly、WorldVLN、ImagineUAV 四篇同期撞车,且都往大模型走。**"小 + 循环状态 + 效率"这条路线在空中领域基本无人占据。**

sub-1B 的空中 VLA **只有 LiteVLA-H 一家,而它放弃了全部任务能力证据**(论文 Limitations 自承"最强证据只是机载计时,仍需更广泛的闭环飞行评测")。小模型方法论(XS-VLA、VLA-Adapter、SimVLA、NanoVLA、SUREFlow)全部成熟于操作与自动驾驶领域,尚未迁入空中长时程任务。这降低了技术风险(有效性已被旁证),同时保住新颖性。**要预判的审稿质疑是"这只是把 X 用到 UAV 上"——所以循环状态与进度监督的设计必须承担真正的创新负载,不能只靠"小"。**

### 新颖性的诚实边界

**"用进度监督循环状态"基本已被占**:VLN 领域 Self-Monitoring Agent(1901.03035, ICLR 2019)就是这个做法;VLA 领域有 ProgVLA(2605.28231)。且 ProgVLA 消融显示去掉进度目标只掉 2.3 分,而去掉压缩模块掉 16 分——**不能把论文押在进度监督上。**

尚未被占的具体组合:

1. **用离散阶段标签监督,而非标量剩余时长回归**,且使状态与 NTP 的定义对齐
2. **监督对象是跨时间步传播的递归状态**,而非每步重算的压缩上下文(ProgVLA 的 `c_t` 不跨步;RB-VLA 的状态跨步但监督是自监督的)——"递归 × 标签监督"这个交叉点是空的
3. **测量出部分可观测的作用域并据此做任务条件化的记忆**——§1 的两个实验目前无人做过
4. **空中长时程 + 过程性指标(TCR / NTP / nDTW)评测记忆机制**

建议的主张形式:*不是"我们加了个辅助损失",而是"我们测量出该基准部分可观测性的精确作用域,证明缺失信息约 1 bit,并据此设计任务条件化的相位状态,同时解释了 RoboMME 观察到的递归训练不稳定性"。*

- **`2603.14363` 的确切标题(已亲自核验 arXiv 全文)是 *AerialVLA: A Vision-Language-Action Model for UAV Navigation via Minimalist End-to-End Control***。曾有"已改名 AeroVLA 并被 ECCV 2026 接收"的说法,**核验后不成立**,按此引用会出错。该文是 OpenVLA-7B / Llama-2 + LoRA,双视图(前视+下视)竖向拼接,模糊方向提示,99 bin 数值 token,3-DoF 动作空间。
  值得单独记一笔:**AerialVLA 明确站在我们的对立面** ——"By intentionally bypassing complex spatiotemporal memory buffers, this minimalist design drastically reduces inference latency and prevents the accumulation of cascading errors from stale states." 这是本领域对"记忆"最直白的反方立场,应当在 related work 中正面引用并用 §1 的测量回应,而不是回避。
- **HUGE-Bench 自身的 "ECCV 2026" 身份未独立核实**:来源是作者 GitHub 仓库标题,arXiv comment 字段为空。间接佐证是作者曾说"接收后释放全部环境",而环境已于 2026-06-24 释放。可信,但引用时建议注明来源。
- HUGE-Bench 仓库 README 写 `NSP`,论文写 `NTP`,复现脚本输出 NSP 字段。
- 论文称 train/test-seen/test-unseen 为 5,330 / 593 / 294,**发布版实际为 5,175 / 576 / 417**(阶段标注 manifest 与 HF 一致)。以发布版为准。
- `info.json` 内部不一致:`total_tasks: 109`、`splits: "0:109"`,而实际 5,175 episodes、1,102 条不同指令。**任何信任 `info.json` 的工具都会索引错位。**
- MemoryVLA 的成本被广泛误传:原文实为 0.187 → 0.194 s(约 4%)、+0.8 GB;网传的 "+30% 延迟 / +5 GB" 是 **MemoryVLA++**(2606.09827)的数字。
- 跨论文比较 Collision Rate **无效**:HUGE-Bench 的 CR(约 1%)基于数字孪生轨迹碰撞判定,AutoFly 的 CR(22–38%)是闭环飞行 episode 失败率。
- LiteVLA-H(2605.00884)与 LiteVLA-Edge(2603.03380)是同组姊妹稿,**均无任务成功率**,仅可引用其"prefill 主导"的延迟分解观察,不可作为空中 VLA 能力或速度前沿。
- 当前 VLM 骨干 UAV 策略最诚实的全机载数字:**VLA-AN 494 ms ≈ 2 Hz(Jetson Orin NX,2B AWQ,由 4100 ms 优化而来)**,分解为 ViT 2350→120 ms、projector+LLM prefill 550→130 ms、decode 1000→230 ms;作者坦承部分视觉网络仍在 Orin NX 的 CPU 上执行,并明说希望换 Jetson Thor 后"接近 10 Hz",即承认当前尚未达到理想实时性。所有更高频率的报告要么用离板 GPU、要么模型 <1B、要么由 action chunking 摊薄。
- **SINGER(2509.18610)的 "20 Hz" 是术语陷阱**:20 Hz 是小型 SV-Net 输出电机指令的频率,语义分支 CLIPSeg 在 Orin Nano 上单独只有 3 Hz、整条图像管线 12–13 Hz,两者异步。且 CLIPSeg 是判别式分割模型,不是生成式 VLM。
- **命名冲突**:`2607.14997` 名为 AeroAct,而另一篇不同的空中 VLN 论文 `2512.08639` 的代码仓库**也叫 AeroAct**。
- **不要经 LiteVLA-H 二手引用**:它自称对标的 AnywhereVLA / FutureVLA / ReMem-VLA 三个系统未经独立验证存在。
